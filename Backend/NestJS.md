# NestJS

**NestJS** is a backend framework that provides more structure than the classical **Express.js** by adopting a more
Spring Boot-style architecture on top of an `express` (default) or `fastify` application under the hood. It is
**TypeScript-first**, heavily **decorator-driven**, and built around **modules**, **dependency injection**, and a clear
separation of layers (controller → service → repository).

**Opinions** :

- **TypeScript-first**: everything is strongly typed; decorators drive metadata and wiring.

- **Modular architecture**: the app is a tree of `@Module`s, each grouping related controllers and providers.

- **Dependency injection everywhere**: shared logic lives in `@Injectable` providers resolved by a hierarchical IoC
  container rather than imported directly.

- **Platform-agnostic core**: the same code runs on Express or Fastify; the HTTP layer is abstracted.

- **Convention over configuration**: the CLI scaffolds a fixed folder layout, naming scheme, and build pipeline.

- **Layered request pipeline**: middleware → guards → interceptors → pipes → handler → interceptors → exception filters.

--- 

## Application Kinds 

It can be used for different types of applications:

- **HTTP / REST API**: the default; a web server exposing REST endpoints (or GraphQL).

- **Microservice**: transport-based apps (TCP, Redis, NATS, Kafka, RabbitMQ, gRPC) using a message/event pattern.

- **WebSockets**: real-time gateways over Socket.IO or `ws`.

- **Standalone application**: no HTTP listener — use Nest's DI container in a CLI, cron worker, or script.

## Installation & Set-Up

Install the **CLI** globally. It scaffolds projects and generates code (controllers, services, modules, etc.).

```bash
npm install -g @nestjs/cli

nest --version          # verify installation
```

### Set-Up Project

```bash
nest new my-app                 # interactive wizard (npm / yarn / pnpm?)
nest new my-app --package-manager npm --skip-git
nest new my-app --dry-run       # simulate creation without writing files
```

The wizard asks for a package manager and scaffolds a ready-to-run project with a testing setup, linting, and a
`main.ts` bootstrap.

```bash
cd my-app
npm run start:dev      # start in watch mode at http://localhost:3000
```

### Manual Install (into an existing project)

```bash
npm install @nestjs/core @nestjs/common rxjs reflect-metadata
npm install @nestjs/platform-express      # or @nestjs/platform-fastify
```

`reflect-metadata` is required; it powers the decorator metadata Nest relies on for DI and routing.

## Project Structure

A typical Nest project scaffolded by the CLI:

```txt
my-app/
├── src/
│   ├── main.ts                 - entry point; bootstraps the application
│   ├── app.module.ts           - root module (imports all feature modules)
│   ├── app.controller.ts       - example controller
│   ├── app.service.ts          - example provider
│   └── users/                  - a feature module (by convention, one folder per domain)
│       ├── users.module.ts     - wires the feature together
│       ├── users.controller.ts - HTTP routes
│       ├── users.service.ts    - business logic
│       ├── dto/                - Data Transfer Objects (request/response shapes)
│       │   ├── create-user.dto.ts
│       │   └── update-user.dto.ts
│       └── entities/           - ORM entities / domain models
│           └── user.entity.ts
├── test/                       - e2e tests
│   └── app.e2e-spec.ts
├── nest-cli.json               - CLI & build configuration
├── tsconfig.json               - TypeScript config
├── package.json
└── ...
```

### `main.ts`

The **entry point** creates the application instance and starts the HTTP listener.

```ts
import { NestFactory } from "@nestjs/core";
import { ValidationPipe } from "@nestjs/common";
import { AppModule } from "./app.module";

async function bootstrap() {

  const app = await NestFactory.create(AppModule);

  app.setGlobalPrefix("api");                    // prefix every route with /api
  app.useGlobalPipes(new ValidationPipe({ whitelist: true }));
  app.enableCors();                              // enable Cross-Origin Resource Sharing

  await app.listen(process.env.PORT ?? 3000);
}
bootstrap(); // start the application
```

- `NestFactory.create(AppModule, options?)`: builds the app from the root module. `options` can set `{ cors, logger, bufferLogs }`.

- `app.setGlobalPrefix(prefix)`: prepends a base path to all routes.

- `app.useGlobalPipes / useGlobalGuards / useGlobalInterceptors / useGlobalFilters`: register app-wide pipeline components.

- `app.enableCors(options?)`: configures CORS.

- `app.listen(port, callback?)`: starts the server (returns a Promise).

### `app.module.ts`

The **root module** ties the application together.

```ts
import { Module } from "@nestjs/common";
import { UsersModule } from "./users/users.module";
import { AppController } from "./app.controller";
import { AppService } from "./app.service";

@Module({
  imports: [UsersModule],          // other modules whose exports we use
  controllers: [AppController],    // request handlers
  providers: [AppService],         // injectable services
})
export class AppModule {}
```

## Decorators

NestJS is **decorator-driven** — metadata attached via decorators tells the framework how to wire and route code.
Decorators fall into a few groups.

**Class decorators** (define the role of a class):

- `@Module(metadata)`: declares a module (`imports`, `controllers`, `providers`, `exports`).
- `@Controller(prefix?)`: declares a request-handling class, optionally with a route prefix.
- `@Injectable(options?)`: marks a class as a provider that the DI container can instantiate and inject.
- `@Catch(...exceptions)`: marks a class as an exception filter for the given exception types.

**Method (route) decorators** (map HTTP verbs to handlers):

- `@Get(path?)`, `@Post(path?)`, `@Put(path?)`, `@Patch(path?)`, `@Delete(path?)`, `@Options(path?)`, `@Head(path?)`, `@All(path?)`.

**Parameter decorators** (extract data from the request):

- `@Param(key?)`: route parameter(s) — `/users/:id`.
- `@Query(key?)`: query-string parameter(s) — `?page=2`.
- `@Body(key?)`: the request body (or a single property of it).
- `@Headers(name?)`: request header(s).
- `@Req()` / `@Request()`, `@Res()` / `@Response()`: the underlying platform request/response objects.
- `@Ip()`, `@HostParam()`, `@Session()`.

**Binding / metadata decorators:**

- `@UseGuards(...guards)`, `@UsePipes(...pipes)`, `@UseInterceptors(...interceptors)`, `@UseFilters(...filters)`.
- `@SetMetadata(key, value)`: attaches custom metadata read later by guards/interceptors (basis of `@Roles`, etc.).
- `@HttpCode(status)`: override the default success status code.
- `@Header(name, value)`: set a response header.
- `@Redirect(url, status)`: redirect the response.

```ts
@Controller("cats")
export class CatsController {
  @Get(":id")
  @HttpCode(200)
  @Header("Cache-Control", "no-store")
  findOne(@Param("id") id: string, @Query("expand") expand?: string) {
    return { id, expand };
  }
}
```

## Modules

A **module** is a class annotated with `@Module` that groups a cohesive set of capabilities. Every app has at least one
**root module**, and features are organized into **feature modules**. Modules form a tree and define DI boundaries.

`@Module` metadata fields:

- `imports`: other modules whose **exported** providers this module needs.
- `controllers`: controllers instantiated within this module.
- `providers`: providers (services, factories, etc.) available for injection **inside** this module.
- `exports`: the subset of `providers` made visible to modules that import this one.

```ts
import { Module } from "@nestjs/common";
import { UsersController } from "./users.controller";
import { UsersService } from "./users.service";

@Module({
  imports: [],
  controllers: [UsersController],
  providers: [UsersService],
  exports: [UsersService],   // let other modules inject UsersService
})
export class UsersModule {}
```

### Shared Modules

Providers are singletons scoped to the DI container. Exporting a provider and importing its module elsewhere shares the
**same instance** — no need to re-declare it.

### Global Modules

- `@Global()`: makes a module's exported providers available everywhere without importing it repeatedly. Use sparingly
  (config, database) — overuse hurts modularity.

```ts
import { Global, Module } from "@nestjs/common";

@Global()
@Module({
  providers: [ConfigService],
  exports: [ConfigService],
})
export class ConfigModule {}
```

### Dynamic Modules

Modules configured at import time (e.g., passing a connection string). A static method returns a `DynamicModule`.

```ts
@Module({})
export class DatabaseModule {
  static forRoot(options: DbOptions): DynamicModule {
    return {
      module: DatabaseModule,
      providers: [{ provide: "DB_OPTIONS", useValue: options }, DatabaseService],
      exports: [DatabaseService],
    };
  }
}

// usage:  imports: [DatabaseModule.forRoot({ url: "..." })]
```

By convention, `forRoot`/`forRootAsync` configure a module once (app-wide), while `forFeature` registers
feature-specific pieces (e.g., specific entities/repositories).

## Controllers

**Controllers** handle incoming requests and return responses. A method's route is the concatenation of the controller
prefix and the method path. Return values are automatically serialized to JSON.

- `@Controller(prefix?)`: declares the controller; `prefix` is prepended to every route.
- Route decorators (`@Get`, `@Post`, …) map an HTTP verb + sub-path to a handler method.
- Whatever a handler returns becomes the response body (objects → JSON, primitives → as-is). Promises and RxJS
  observables are awaited/subscribed automatically.

```ts
import {
  Controller, Get, Post, Put, Patch, Delete,
  Param, Query, Body, HttpCode, HttpStatus,
} from "@nestjs/common";
import { UsersService } from "./users.service";
import { CreateUserDto } from "./dto/create-user.dto";
import { UpdateUserDto } from "./dto/update-user.dto";

@Controller("users")
export class UsersController {
  constructor(private readonly usersService: UsersService) {}

  // GET /users?limit=10
  @Get()
  findAll(@Query("limit") limit = "10") {
    return this.usersService.findAll(Number(limit));
  }

  // GET /users/42
  @Get(":id")
  findOne(@Param("id") id: string) {
    return this.usersService.findOne(Number(id));
  }

  // POST /users
  @Post()
  @HttpCode(HttpStatus.CREATED)                 // 201
  create(@Body() dto: CreateUserDto) {
    return this.usersService.create(dto);
  }

  // PATCH /users/42
  @Patch(":id")
  update(@Param("id") id: string, @Body() dto: UpdateUserDto) {
    return this.usersService.update(Number(id), dto);
  }

  // DELETE /users/42
  @Delete(":id")
  @HttpCode(HttpStatus.NO_CONTENT)              // 204
  remove(@Param("id") id: string) {
    return this.usersService.remove(Number(id));
  }
}
```

### Route Parameters & Wildcards

```ts
@Get(":id")                       // /users/42          → @Param("id")
@Get(":id/posts/:postId")         // /users/42/posts/7  → @Param("postId")
@Get("ab*cd")                     // wildcard route
```

### Request Payload Objects

| Decorator | Extracts | Example |
|-----------|----------|---------|
| `@Param(key?)` | Route params | `@Param("id") id: string` |
| `@Query(key?)` | Query string | `@Query("page") page: string` |
| `@Body(key?)` | Request body | `@Body() dto: CreateUserDto` |
| `@Headers(name?)` | Request headers | `@Headers("authorization") auth: string` |
| `@Req()` | Full request object | `@Req() req: Request` |
| `@Res()` | Full response object | `@Res() res: Response` |
| `@Ip()` | Client IP | `@Ip() ip: string` |
| `@Session()` | Session object | `@Session() session: Record<string, any>` |

> Injecting `@Res()` switches Nest into **manual response mode** — you must call `res.send()` yourself and Nest no longer
> serializes the return value. Prefer returning values unless you need low-level control (use `@Res({ passthrough: true })`
> to keep Nest's handling while accessing the response).

### Response Handling

- `@HttpCode(status)`: sets the success status code (default `200`, or `201` for `@Post`).
- `@Header(name, value)`: sets a response header.
- `@Redirect(url, statusCode)`: redirects; a handler can also return `{ url, statusCode }` to redirect dynamically.

```ts
@Post()
@Header("X-Powered-By", "Nest")
@Redirect("https://nestjs.com", 302)
create() { /* ... */ }
```

## Providers

**Providers** are the core of Nest's dependency injection — services, repositories, factories, helpers, and any class
annotated with `@Injectable`. They encapsulate business logic and are injected into controllers or other providers.

- `@Injectable(options?)`: marks a class as a provider the container can instantiate and inject.
  - `options.scope`: `Scope.DEFAULT` (singleton), `Scope.REQUEST` (per request), or `Scope.TRANSIENT` (new per injection).

```ts
import { Injectable, NotFoundException } from "@nestjs/common";
import { CreateUserDto } from "./dto/create-user.dto";

export interface User { id: number; name: string; email: string; }

@Injectable()
export class UsersService {
  private users: User[] = [];
  private nextId = 1;

  findAll(limit?: number): User[] {
    return limit ? this.users.slice(0, limit) : this.users;
  }

  findOne(id: number): User {
    const user = this.users.find((u) => u.id === id);
    if (!user) throw new NotFoundException(`User ${id} not found`);
    return user;
  }

  create(dto: CreateUserDto): User {
    const user: User = { id: this.nextId++, ...dto };
    this.users.push(user);
    return user;
  }

  remove(id: number): void {
    this.users = this.users.filter((u) => u.id !== id);
  }
}
```

## Dependency Injection

Nest has a **hierarchical IoC container** that resolves a class's dependencies from its constructor parameter types.
Register a class in a module's `providers`, and Nest instantiates and injects it wherever requested.

- **Constructor injection** (standard): declare dependencies as constructor parameters. Nest matches by type.

- `@Inject(token)`: inject by a custom token (needed for non-class providers like strings/symbols or interfaces).

- `@Optional()`: mark a dependency as optional — no error if it can't be resolved.

```ts
@Injectable()
export class OrdersService {
  constructor(
    private readonly usersService: UsersService,          // by type
    @Inject("PAYMENT_GATEWAY") private gateway: Gateway,   // by token
    @Optional() private readonly logger?: LoggerService,   // optional
  ) {}
}
```

### Provider Registration Types

A provider entry can take several forms:

- **Standard (shorthand)**: `providers: [UsersService]` — class is both token and implementation.

- `useClass`: bind a token to a concrete class (swap implementations per environment).

- `useValue`: provide a ready-made value/object (config, constants, mocks in tests).

- `useFactory`: compute the provider with a factory function; supports `inject` for its own dependencies and `async`.

- `useExisting`: create an alias pointing to another existing provider.

```ts
@Module({
  providers: [
    UsersService,                                            // standard

    { provide: LoggerService, useClass: ProdLoggerService }, // useClass

    { provide: "API_KEY", useValue: process.env.API_KEY },   // useValue

    {                                                        // useFactory
      provide: "DB_CONNECTION",
      useFactory: async (config: ConfigService) => {
        return createConnection(config.get("DB_URL"));
      },
      inject: [ConfigService],
    },

    { provide: "AliasLogger", useExisting: LoggerService },  // useExisting
  ],
})
export class AppModule {}
```

### Injection Scopes

| Scope | Lifetime | Use when |
|-------|----------|----------|
| `Scope.DEFAULT` | Singleton — one instance for the whole app | Almost always (default) |
| `Scope.REQUEST` | One instance per incoming request | Need per-request state (e.g., request user) |
| `Scope.TRANSIENT` | New instance for each consumer that injects it | Stateful helpers not to be shared |

```ts
@Injectable({ scope: Scope.REQUEST })
export class RequestScopedService {}
```

> Request-scoped providers bubble up: any provider that depends on one also becomes request-scoped, which has a
> performance cost. Use the default singleton scope unless you truly need per-request state.

## DTOs & Validation

A **DTO (Data Transfer Object)** defines the shape of a request payload. Combined with `class-validator` and
`class-transformer`, Nest validates and transforms incoming data automatically via the `ValidationPipe`.

```bash
npm install class-validator class-transformer
```

- `ValidationPipe`: validates incoming payloads against DTO decorators and (optionally) strips/transforms them.
  - `whitelist: true`: strip properties without validation decorators.
  - `forbidNonWhitelisted: true`: throw if unknown properties are present.
  - `transform: true`: auto-transform payloads into DTO class instances (and primitive types).
  - `transformOptions`, `disableErrorMessages`, `groups`: finer control.

**Common `class-validator` decorators:**

- `@IsString()`, `@IsInt()`, `@IsNumber()`, `@IsBoolean()`, `@IsEmail()`, `@IsUUID()`, `@IsEnum(E)`.
- `@IsNotEmpty()`, `@IsOptional()`, `@MinLength(n)`, `@MaxLength(n)`, `@Min(n)`, `@Max(n)`.
- `@Matches(regex)`, `@IsArray()`, `@ValidateNested()`, `@Type(() => Class)` (from `class-transformer`).

```ts
import { IsEmail, IsInt, IsOptional, IsString, Min, MinLength } from "class-validator";

export class CreateUserDto {
  @IsString()
  @MinLength(2)
  name: string;

  @IsEmail()
  email: string;

  @IsOptional()
  @IsInt()
  @Min(0)
  age?: number;
}
```

Enable validation globally in `main.ts`:

```ts
app.useGlobalPipes(new ValidationPipe({ whitelist: true, transform: true }));
```

### Mapped Types (partial / pick / omit)

`@nestjs/mapped-types` (or `@nestjs/swagger`) derives DTOs from other DTOs, avoiding duplication.

- `PartialType(Dto)`: all properties become optional (ideal for `PATCH` updates).
- `PickType(Dto, keys)`: keep only selected properties.
- `OmitType(Dto, keys)`: drop selected properties.
- `IntersectionType(A, B)`: combine two DTOs.

```ts
import { PartialType } from "@nestjs/mapped-types";
import { CreateUserDto } from "./create-user.dto";

export class UpdateUserDto extends PartialType(CreateUserDto) {}
```

## Pipes

**Pipes** transform or validate the input to a route handler. They run just before the handler, receiving the argument
value and its metadata. A pipe either returns a (possibly transformed) value or throws to abort the request.

**Built-in pipes** (from `@nestjs/common`):

- `ValidationPipe`: validate/transform against DTO decorators.
- `ParseIntPipe`, `ParseFloatPipe`, `ParseBoolPipe`: parse and validate primitive types.
- `ParseUUIDPipe`, `ParseArrayPipe`, `ParseEnumPipe`.
- `DefaultValuePipe(value)`: supply a fallback when a param is missing.

Pipes can be applied at three levels:

- **Parameter-level**: `@Param("id", ParseIntPipe)`.
- **Handler-level**: `@UsePipes(new ValidationPipe())` on a method.
- **Global**: `app.useGlobalPipes(...)`.

```ts
@Get(":id")
findOne(
  @Param("id", ParseIntPipe) id: number,
  @Query("page", new DefaultValuePipe(1), ParseIntPipe) page: number,
) {
  return this.usersService.findOne(id);
}
```

### Custom Pipes

Implement `PipeTransform` and the `transform(value, metadata)` method.

- `PipeTransform<T, R>`: interface with `transform(value: T, metadata: ArgumentMetadata): R`.
- `metadata`: `{ type, metatype, data }` — where the value came from (`body`/`query`/`param`), its declared type, and the param key.

```ts
import { PipeTransform, Injectable, ArgumentMetadata, BadRequestException } from "@nestjs/common";

@Injectable()
export class ParsePositiveIntPipe implements PipeTransform<string, number> {
  transform(value: string, _metadata: ArgumentMetadata): number {
    const n = parseInt(value, 10);
    if (isNaN(n) || n <= 0) {
      throw new BadRequestException(`"${value}" is not a positive integer`);
    }
    return n;
  }
}

// usage:  @Param("id", ParsePositiveIntPipe) id: number
```

## Guards

**Guards** decide whether a request may proceed to the route handler. They implement authorization logic and run
**after** middleware but **before** interceptors and pipes.

- `CanActivate`: interface with `canActivate(context): boolean | Promise<boolean> | Observable<boolean>`.
  Return `true` to allow, `false` (→ `403 Forbidden`) or throw to deny.
- `ExecutionContext`: wraps the current request; `context.switchToHttp().getRequest()` retrieves the HTTP request.
- `@UseGuards(...guards)`: bind guards at controller or handler level; `app.useGlobalGuards(...)` for app-wide.

```ts
import { CanActivate, ExecutionContext, Injectable, UnauthorizedException } from "@nestjs/common";

@Injectable()
export class AuthGuard implements CanActivate {
  canActivate(context: ExecutionContext): boolean {
    const request = context.switchToHttp().getRequest();
    const token = request.headers["authorization"];
    if (!token) throw new UnauthorizedException("Missing token");
    request.user = this.verify(token);   // attach for downstream use
    return true;
  }

  private verify(token: string) { /* validate JWT, return payload */ }
}

// usage:  @UseGuards(AuthGuard)
```

### Role-Based Guards (with metadata)

Combine `@SetMetadata` (or a custom `@Roles` decorator) with `Reflector` to read metadata at runtime.

```ts
import { SetMetadata } from "@nestjs/common";
export const Roles = (...roles: string[]) => SetMetadata("roles", roles);

import { Injectable, CanActivate, ExecutionContext } from "@nestjs/common";
import { Reflector } from "@nestjs/core";

@Injectable()
export class RolesGuard implements CanActivate {
  constructor(private reflector: Reflector) {}

  canActivate(context: ExecutionContext): boolean {
    const required = this.reflector.getAllAndOverride<string[]>("roles", [
      context.getHandler(),
      context.getClass(),
    ]);
    if (!required) return true;                 // no restriction
    const { user } = context.switchToHttp().getRequest();
    return required.some((role) => user?.roles?.includes(role));
  }
}

// usage:
// @Roles("admin")
// @UseGuards(AuthGuard, RolesGuard)
// @Delete(":id") remove() { ... }
```

## Interceptors

**Interceptors** wrap handler execution, letting you run logic **before and after** the handler. They are built on RxJS
and are ideal for logging, response shaping, caching, and timeouts.

- `NestInterceptor`: interface with `intercept(context, next): Observable<any>`.
- `CallHandler.handle()`: returns an `Observable` of the handler's result; use RxJS operators (`map`, `tap`, `catchError`, `timeout`) to transform it.
- `@UseInterceptors(...)`: bind at controller/handler level; `app.useGlobalInterceptors(...)` for app-wide.

```ts
import { CallHandler, ExecutionContext, Injectable, NestInterceptor } from "@nestjs/common";
import { Observable } from "rxjs";
import { map, tap } from "rxjs/operators";

@Injectable()
export class TransformInterceptor implements NestInterceptor {
  intercept(context: ExecutionContext, next: CallHandler): Observable<any> {
    const now = Date.now();
    return next.handle().pipe(
      map((data) => ({ data, timestamp: new Date().toISOString() })),  // wrap response
      tap(() => console.log(`Handled in ${Date.now() - now}ms`)),      // side effect
    );
  }
}
```

Built-in interceptors include `ClassSerializerInterceptor` (applies `class-transformer` `@Exclude`/`@Expose`),
`CacheInterceptor`, and `TimeoutInterceptor`.

## Middleware

**Middleware** runs **before** the route handler and has access to the raw `req`, `res`, and `next` — identical to
Express middleware. Use it for logging, request enrichment, or third-party middleware (helmet, cookie-parser).

- `NestMiddleware`: interface with `use(req, res, next)`.
- Registered in a module's `configure(consumer: MiddlewareConsumer)` method (the module must implement `NestModule`).
  - `consumer.apply(...middleware).forRoutes(...)`: attach middleware to routes.
  - `.exclude(...)`: skip specific routes.

```ts
import { Injectable, NestMiddleware, NestModule, MiddlewareConsumer, Module, RequestMethod } from "@nestjs/common";
import { Request, Response, NextFunction } from "express";

@Injectable()
export class LoggerMiddleware implements NestMiddleware {
  use(req: Request, res: Response, next: NextFunction) {
    console.log(`[${req.method}] ${req.originalUrl}`);
    next();                       // pass control to the next handler
  }
}

@Module({ /* ... */ })
export class AppModule implements NestModule {
  configure(consumer: MiddlewareConsumer) {
    consumer
      .apply(LoggerMiddleware)
      .exclude({ path: "health", method: RequestMethod.GET })
      .forRoutes("*");           // all routes
  }
}
```

### Request Lifecycle Order

```txt
Incoming request
  → Middleware
  → Guards
  → Interceptors (pre-controller)
  → Pipes
  → Route handler (controller method)
  → Interceptors (post-controller)
  → Exception filters (only if an exception is thrown)
  → Response
```

## Exception Handling

Nest ships a global **exceptions layer** that turns thrown exceptions into HTTP responses. Throw one of the built-in
`HttpException` subclasses, or create custom exceptions.

**Built-in HTTP exceptions** (from `@nestjs/common`):

- `BadRequestException` (400), `UnauthorizedException` (401), `ForbiddenException` (403), `NotFoundException` (404).
- `ConflictException` (409), `GoneException` (410), `UnprocessableEntityException` (422).
- `InternalServerErrorException` (500), `BadGatewayException` (502), `ServiceUnavailableException` (503).
- Base class: `new HttpException(response, status)`.

```ts
throw new NotFoundException("User not found");
throw new HttpException({ code: "E_LIMIT", message: "Too many" }, HttpStatus.TOO_MANY_REQUESTS);
```

### Custom Exception Filters

- `@Catch(...types)`: marks a class as a filter for the given exception type(s) (omit args to catch everything).
- `ExceptionFilter`: interface with `catch(exception, host: ArgumentsHost)`.
- `ArgumentsHost`: abstraction over the execution context; `host.switchToHttp()` yields the request/response.
- `@UseFilters(...)`: bind at handler/controller level; `app.useGlobalFilters(...)` for app-wide.

```ts
import { ExceptionFilter, Catch, ArgumentsHost, HttpException } from "@nestjs/common";
import { Request, Response } from "express";

@Catch(HttpException)
export class HttpExceptionFilter implements ExceptionFilter {
  catch(exception: HttpException, host: ArgumentsHost) {
    const ctx = host.switchToHttp();
    const response = ctx.getResponse<Response>();
    const request = ctx.getRequest<Request>();
    const status = exception.getStatus();

    response.status(status).json({
      statusCode: status,
      path: request.url,
      timestamp: new Date().toISOString(),
      message: exception.getResponse(),
    });
  }
}
```

## Database Binding

Nest is ORM-agnostic. The most common integrations are **TypeORM**, **Prisma**, and **Mongoose** (MongoDB). This
section covers **TypeORM**, which mirrors the Spring Data JPA repository model.

```bash
npm install @nestjs/typeorm typeorm pg    # pg driver for PostgreSQL
```

### Connection Setup

- `TypeOrmModule.forRoot(options)`: configures the database connection (or `forRootAsync` to inject `ConfigService`).
  - `type`: `"postgres" | "mysql" | "sqlite" | ...`.
  - `entities`: entity classes (or glob paths) to register.
  - `synchronize`: auto-create/alter schema from entities — **development only**, never in production.
  - `autoLoadEntities`: register entities declared via `forFeature` automatically.

```ts
import { TypeOrmModule } from "@nestjs/typeorm";

@Module({
  imports: [
    TypeOrmModule.forRootAsync({
      inject: [ConfigService],
      useFactory: (config: ConfigService) => ({
        type: "postgres",
        url: config.get("DB_URL"),
        autoLoadEntities: true,
        synchronize: config.get("NODE_ENV") !== "production",
      }),
    }),
  ],
})
export class AppModule {}
```

### Entity

- `@Entity(name?)`: maps a class to a database table.
- `@PrimaryGeneratedColumn(strategy?)`: auto-generated primary key (`"increment"` default, or `"uuid"`).
- `@Column(options?)`: maps a field to a column (`{ type, nullable, unique, length, default }`).
- `@CreateDateColumn()` / `@UpdateDateColumn()`: auto-managed timestamps.
- Relations: `@OneToOne`, `@OneToMany`, `@ManyToOne`, `@ManyToMany` with `@JoinColumn` / `@JoinTable`.

```ts
import {
  Entity, PrimaryGeneratedColumn, Column, CreateDateColumn, OneToMany,
} from "typeorm";

@Entity("users")
export class User {
  @PrimaryGeneratedColumn()
  id: number;

  @Column({ length: 100 })
  name: string;

  @Column({ unique: true })
  email: string;

  @Column({ default: true })
  isActive: boolean;

  @CreateDateColumn()
  createdAt: Date;

  @OneToMany(() => Post, (post) => post.author)
  posts: Post[];
}
```

### Repository Injection

- `TypeOrmModule.forFeature([Entity])`: registers entity repositories for a feature module.
- `@InjectRepository(Entity)`: injects the `Repository<Entity>` for that entity.

**Common `Repository<T>` methods:**

- `find(options?)`, `findOne(options)`, `findOneBy(where)`, `findBy(where)`: query rows.
- `create(partial)`: build an entity instance (not saved yet).
- `save(entity)`: insert or update (upsert by primary key).
- `update(criteria, partial)`, `delete(criteria)`, `remove(entity)`.
- `count(options?)`, `createQueryBuilder(alias)`: aggregate and complex queries.

```ts
// users.module.ts
@Module({
  imports: [TypeOrmModule.forFeature([User])],
  controllers: [UsersController],
  providers: [UsersService],
})
export class UsersModule {}

// users.service.ts
import { InjectRepository } from "@nestjs/typeorm";
import { Repository } from "typeorm";

@Injectable()
export class UsersService {
  constructor(
    @InjectRepository(User) private readonly repo: Repository<User>,
  ) {}

  findAll(): Promise<User[]> {
    return this.repo.find();
  }

  async findOne(id: number): Promise<User> {
    const user = await this.repo.findOneBy({ id });
    if (!user) throw new NotFoundException(`User ${id} not found`);
    return user;
  }

  create(dto: CreateUserDto): Promise<User> {
    const user = this.repo.create(dto);   // build instance
    return this.repo.save(user);          // persist
  }

  async update(id: number, dto: UpdateUserDto): Promise<User> {
    await this.repo.update(id, dto);
    return this.findOne(id);
  }

  async remove(id: number): Promise<void> {
    await this.repo.delete(id);
  }
}
```

### Password Hashing

### JWT Authentication

```ts
// auth.module.ts
@Module({
  imports: [
    JwtModule.registerAsync({
      inject: [ConfigService],
      useFactory: (config: ConfigService) => ({
        secret: config.get("JWT_SECRET"),
        signOptions: { expiresIn: "1h" },
      }),
    }),
  ],
  providers: [AuthService, JwtStrategy],
})
export class AuthModule {}

// auth.service.ts
@Injectable()
export class AuthService {
  constructor(
    private readonly users: UsersService,
    private readonly jwt: JwtService,
  ) {}

  async validateUser(email: string, password: string) {
    const user = await this.users.findByEmail(email);
    if (user && (await bcrypt.compare(password, user.password))) {
      return user;
    }
    throw new UnauthorizedException("Invalid credentials");
  }

  async login(user: User) {
    const payload = { sub: user.id, email: user.email, roles: user.roles };
    return { access_token: this.jwt.sign(payload) };
  }
}
```

### Passport JWT Strategy

- `PassportStrategy(Strategy)`: base class to extend for a strategy.
- `validate(payload)`: called after the token is verified; its return value is attached to `request.user`.

```ts
import { Injectable } from "@nestjs/common";
import { PassportStrategy } from "@nestjs/passport";
import { ExtractJwt, Strategy } from "passport-jwt";

@Injectable()
export class JwtStrategy extends PassportStrategy(Strategy) {
  constructor(config: ConfigService) {
    super({
      jwtFromRequest: ExtractJwt.fromAuthHeaderAsBearerToken(),
      ignoreExpiration: false,
      secretOrKey: config.get("JWT_SECRET"),
    });
  }

  async validate(payload: { sub: number; email: string; roles: string[] }) {
    return { userId: payload.sub, email: payload.email, roles: payload.roles };
  }
}
```

## Permissions

Authorization (who may do what) builds on guards. Two common approaches:

### Role-Based Access Control (RBAC)

Use the `@Roles` decorator + `RolesGuard` shown in the [Guards](#guards) section. Attach roles per handler and enforce
them globally or per-controller.

```ts
@Roles("admin")
@UseGuards(AuthGuard("jwt"), RolesGuard)
@Delete(":id")
remove(@Param("id") id: string) { /* only admins reach here */ }
```

### Claims / Attribute-Based (CASL)

For fine-grained, resource-level rules, `@casl/ability` defines what a user `can`/`cannot` do on subjects, evaluated
inside a guard or service.

```ts
// ability.factory.ts
import { AbilityBuilder, PureAbility } from "@casl/ability";

export function defineAbilityFor(user: User) {
  const { can, cannot, build } = new AbilityBuilder(PureAbility);
  if (user.roles.includes("admin")) {
    can("manage", "all");                       // full access
  } else {
    can("read", "Article");
    can("update", "Article", { authorId: user.id });   // only own articles
    cannot("delete", "Article");
  }
  return build();
}

// usage in a service/guard:
// const ability = defineAbilityFor(user);
// if (!ability.can("update", article)) throw new ForbiddenException();
```

## Tests

Nest integrates with **Jest**. The `@nestjs/testing` package builds an isolated testing module where providers can be
mocked and overridden.

- `Test.createTestingModule(metadata)`: builds a testing module (same shape as `@Module`).
- `.overrideProvider(token).useValue(mock)`: replace a provider with a mock/stub.
- `moduleRef.get(Token)` / `.resolve(Token)`: retrieve an instance from the test container.

### Unit Test (service with a mocked repository)

```ts
import { Test, TestingModule } from "@nestjs/testing";
import { getRepositoryToken } from "@nestjs/typeorm";
import { Repository } from "typeorm";
import { UsersService } from "./users.service";
import { User } from "./entities/user.entity";

describe("UsersService", () => {
  let service: UsersService;
  let repo: Repository<User>;

  const mockRepo = {
    find: jest.fn(),
    findOneBy: jest.fn(),
    create: jest.fn(),
    save: jest.fn(),
  };

  beforeEach(async () => {
    const module: TestingModule = await Test.createTestingModule({
      providers: [
        UsersService,
        { provide: getRepositoryToken(User), useValue: mockRepo },
      ],
    }).compile();

    service = module.get<UsersService>(UsersService);
    repo = module.get(getRepositoryToken(User));
  });

  afterEach(() => jest.clearAllMocks());

  it("returns all users", async () => {
    const users = [{ id: 1, name: "Alice" }] as User[];
    mockRepo.find.mockResolvedValue(users);

    await expect(service.findAll()).resolves.toEqual(users);
    expect(repo.find).toHaveBeenCalledTimes(1);
  });

  it("throws when user is missing", async () => {
    mockRepo.findOneBy.mockResolvedValue(null);
    await expect(service.findOne(99)).rejects.toThrow("User 99 not found");
  });
});
```

### E2E Test (full HTTP stack with supertest)

```ts
import { Test } from "@nestjs/testing";
import { INestApplication, ValidationPipe } from "@nestjs/common";
import * as request from "supertest";
import { AppModule } from "../src/app.module";

describe("Users (e2e)", () => {
  let app: INestApplication;

  beforeAll(async () => {
    const moduleRef = await Test.createTestingModule({
      imports: [AppModule],
    }).compile();

    app = moduleRef.createNestApplication();
    app.useGlobalPipes(new ValidationPipe({ whitelist: true }));
    await app.init();
  });

  afterAll(async () => await app.close());

  it("POST /users creates a user", () => {
    return request(app.getHttpServer())
      .post("/users")
      .send({ name: "Alice", email: "alice@example.com" })
      .expect(201)
      .expect((res) => {
        expect(res.body.id).toBeDefined();
        expect(res.body.email).toBe("alice@example.com");
      });
  });

  it("POST /users rejects invalid body", () => {
    return request(app.getHttpServer())
      .post("/users")
      .send({ name: "", email: "not-an-email" })
      .expect(400);
  });
});
```

## Lifecycle Hooks

Nest calls **lifecycle hooks** on providers and controllers during startup and shutdown. Implement the matching
interface.

| Hook | Interface | When it runs |
|------|-----------|-------------|
| `onModuleInit()` | `OnModuleInit` | Once, after the host module's dependencies are resolved |
| `onApplicationBootstrap()` | `OnApplicationBootstrap` | Once, after all modules are initialized |
| `onModuleDestroy()` | `OnModuleDestroy` | On shutdown, before the module is destroyed |
| `beforeApplicationShutdown(signal?)` | `BeforeApplicationShutdown` | On shutdown, before connections close |
| `onApplicationShutdown(signal?)` | `OnApplicationShutdown` | On shutdown, last hook to run |

```ts
import { Injectable, OnModuleInit, OnModuleDestroy } from "@nestjs/common";

@Injectable()
export class ConnectionService implements OnModuleInit, OnModuleDestroy {
  async onModuleInit() {
    await this.connect();          // open pools, warm caches
  }

  async onModuleDestroy() {
    await this.disconnect();       // clean up resources
  }
}
```

> Shutdown hooks only fire if you enable them: `app.enableShutdownHooks()` in `main.ts`.

## Microservices

Nest can run as a **microservice** using a message-based transport instead of HTTP. The same DI and decorator model
applies, with `@MessagePattern` / `@EventPattern` replacing HTTP route decorators.

```bash
npm install @nestjs/microservices
```

- `NestFactory.createMicroservice(Module, { transport, options })`: bootstraps a microservice.
  - `transport`: `Transport.TCP | REDIS | NATS | MQTT | RMQ | KAFKA | GRPC`.
- `@MessagePattern(pattern)`: handles a **request-response** message.
- `@EventPattern(pattern)`: handles a **fire-and-forget** event.
- `ClientProxy.send(pattern, data)`: send a request (returns an `Observable`).
- `ClientProxy.emit(pattern, data)`: emit an event.

```ts
// main.ts (microservice)
const app = await NestFactory.createMicroservice(AppModule, {
  transport: Transport.TCP,
  options: { host: "0.0.0.0", port: 3001 },
});
await app.listen();

// message handler
@Controller()
export class MathController {
  @MessagePattern({ cmd: "sum" })
  sum(data: number[]): number {
    return data.reduce((a, b) => a + b, 0);
  }

  @EventPattern("user_created")
  handleUserCreated(payload: { id: number }) {
    // side effects — no response expected
  }
}
```
